Link Card 是 macOS 菜单栏 App，负责创建 Link 付款请求、读取批准后的虚拟卡信息和取消请求。它不会替你在商家网站下单，也不会自动提交商家付款表单。

本页截图来自真实界面代码的离线演示窗口。账户、授权短语、请求和卡信息均为虚构示例；Costco 为默认商家示例，演示卡信息不能用于付款。

首次安装请先阅读安装指南，下载安装最新版 App。

1. 核心功能：显示与复制 Visa 虚拟卡

批准后直接查看卡号、CVC／CVV、卡面有效期和账单地址，并复制到商家的付款页面。 下图展示 Visa 虚拟卡；实际卡组织及可用字段以 Link 返回结果为准。

卡信息展示示例：图中全部为虚构数据，不是真实付款凭证。

下方表格显示以下字段，未返回的字段显示为 —：

字段 含义
Card number Link 返回的虚拟卡卡号
CVC 虚拟卡安全码，也称 CVV
Expiration 卡的月份／年份有效期
Billing address 返回的账单地址
Brand 卡组织
Valid until Link 返回的卡凭证实际截止时间；缺失时显示 —，与请求到期时间、卡面有效期分别展示
Request expiry Link 返回的请求到期时间
Spend request ID 请求 ID，通常以 lsrq_ 开头
Status 请求当前状态
Merchant / Merchant URL 创建请求时填写的商家名称和网址
Context 购买用途
Created at 请求创建时间

已有批准请求，如何显示？

  1. 切换到 请求 / 历史。
  2. 点击 刷新列表。
  3. 选中要查看的请求。
  4. 点击 显示卡信息 Show。

卡号、CVC／CVV 和卡面有效期旁各有独立的 复制 按钮，点击后显示「已复制」，可直接粘贴到商家结账页。缺失字段不能复制。也可选中文本后按 ⌘C 复制。App 不会自动复制，也不会自动填写商家页面。完整卡号和 CVC 会直接显示在面板内。

点击 清除卡信息 可清空当前显示。收起面板也会清除卡信息显示，等待批准可继续；不会取消服务端请求。卡响应使用临时网络会话处理，不会写成卡信息 JSON 文件。

第一次使用？继续阅读下面的启动、登录、创建和批准流程。未批准的请求不会显示完整卡信息。

2. 菜单栏下拉面板

安装后打开 LinkCard.app，点击 macOS 顶部菜单栏的信用卡图标，即可直接展开操作面板。v2.7.0 起不再打开独立主窗口。

  • 点击图标展开或收起；点击面板外或按 Esc 也可收起。
  • 面板内可以查看请求、创建、批准、退出登录和检查更新；内容较多时向下滚动。
  • 右键点击图标可打开「检查更新…」「退出」等快捷菜单；面板底部也提供「退出」。
  • 收起面板会清除卡信息显示，已有请求保留在 Link。等待批准可以继续；批准后再次展开面板即可读取卡信息。

切换语言

面板顶部提供 中文 / English 切换控件。切换后，按钮、菜单栏菜单、确认框、卡信息字段和已有状态提示会即时更新，重启后也会保留选择。商家名称、用途、请求 ID 和卡信息本身不会被翻译。

面板布局与输入快捷键

面板会根据屏幕可用空间调整尺寸，内容较多时可纵向滚动。下方早期版本截图用于展示字段内容；v2.7.0 起实际界面为菜单栏下拉面板。

窄窗口单列 滚动至底部

所有文本输入框支持 ⌘C 复制、⌘V 粘贴、⌘X 剪切、⌘A 全选、⌘Z 撤销、⇧⌘Z 重做，也可使用 macOS 的「编辑」菜单。先点击输入框，将光标放入其中；⌘A 后粘贴可替换整个字段。付款方式下拉选择后，其 ID 仍可手动粘贴修改。Context 自动生成，无需输入；可选中文本复制。

自动更新（v2.6.0 起）

底部提供「检查更新…」按钮和「自动检查更新」开关，菜单栏也有检查入口。自动检查默认每天一次；关闭后仍可手动检查。发现新版时，按 Sparkle 窗口提示下载、安装并重启；安装前请完成当前操作。更新清单和下载包都会验证签名。第一次从旧版升级到带更新功能的版本，仍需手动下载替换一次。

3. 登录 Link

  1. 点击标题下方的 登录 Link。
  2. 点击 打开 Link 登录授权 ↗，进入官方 Link 网站。
  3. 在浏览器登录自己的 Link 账户，根据页面要求输入 App 显示的授权短语并完成授权。
  4. 返回 App，等待登录完成。右上角的登录按钮会替换为「已登录」和 Link 返回的姓名／邮箱。

点击授权链接，在官方 Link 页面完成登录；图中短语仅为演示。

重新打开 App 时会自动检查登录并读取账户信息；如果登录失效且无法自动续期，会重新显示登录按钮。临时网络故障不会直接把已有登录标记为退出，账户信息无法加载时会显示提示。

这是授权 App 访问 Link，和稍后批准某一笔购买请求是两个独立步骤。独立 App 登录保存在 macOS Keychain 中，无需安装 link-cli、Node.js 或 npm。

如果本机已有尚未过期的 CLI 登录，App 可以只读复用其 access token，不会修改 CLI 配置或使用 CLI 的 refresh token。提示过期后，点击 App 的「登录 Link」建立独立登录即可。

退出登录

登录后，账户信息旁会显示 退出登录。点击后会清除本 App 的 Keychain 登录凭证、账户信息、卡信息和本地列表，并停止等待批准。退出后显示「登录 Link」，下次启动也不会自动复用 link-cli 的登录；重新登录即可查看服务端已有请求。

此操作只退出本 App，不修改 link-cli 配置、不退出浏览器中的 Link，也不会取消已有付款请求。需要撤销服务端授权时，请在 Link 中管理连接。

4. 创建付款请求

先在商家网站确认要购买的商品和结账总金额，再回到 App：

  1. 选择 创建 Generate 页签。
  2. 在付款方式旁点击 加载。
  3. 从下拉列表选择付款方式；选择后，「付款方式 ID」会自动填入。也可以手动填写已有的付款方式 ID。
  4. 填写下列信息。

商家默认填入 Costco 和 https://www.costco.com，可以修改。金额和商品框中的浅色文字只是示例，不会自动提交，必须填入实际购买内容。USD 金额按美分填写，最低 50（$0.50）；1500 = $15.00，50000 = $500.00。用途说明会随字段自动更新，无需手填。

英文界面示例：金额 1500 配合 usd 表示 $15.00。

字段 怎么填 示例
付款方式 ID Link 中用于支付的付款方式，不是 spend request ID 从下拉列表选择
商家名称 实际收款商家，默认 Costco，可修改 Costco
商家 URL 完整的 HTTP/HTTPS 地址，默认 Costco 网址，可修改 https://www.costco.com
金额 币种的最小单位，填写正整数 USD $15.00 填 1500
币种 三字母币种代码 usd
商品 本次购买内容；当前表单固定数量为 1，商品名不要包含逗号 Meal credit
用途 Context 根据商家、URL、商品、金额和币种自动生成，无需填写 创建前可在确认框核对
  1. 点击 检查并创建请求…。
  2. 在确认框中核对商家、URL、金额、商品和用途。
  3. 点击 创建并请求批准。仅填写表单不会提交请求。

确认框供你检查内容；点击 Back 可以返回修改。

金额必须结合币种理解。例如 usd 下 10000 表示 $100.00，而不是 $10,000。请求金额和状态也不等于商家最终结算金额。

此客户端不支持自定义请求到期时间，创建时不提交 expires_at。卡面有效期和实际可用截止时间以 Link 返回结果为准。

5. 批准请求并自动显示卡信息

  1. 创建成功后自动进入 待批准 页，点击 在 Link 中批准请求 ↗。也可以在此页选择之前的待批准请求，核对商家、金额及自动生成的用途；若尚无链接，点击 获取批准链接。
  2. 在 Link 官方页面核对并亲自批准本次请求。
  3. 等待 Link 批准。App 每两秒检查一次状态，最多等待十分钟；发现已批准且面板展开时自动读取卡信息；面板收起时，再次展开后读取。
  4. 如果没有自动更新，点击 已批准，刷新卡信息，或在列表中选中请求后点击 显示卡信息 Show。

查看之前的请求： 打开「待批准」，点击「刷新列表」，选中请求查看商家 URL、请求金额和用途。没有链接时点击「获取批准链接」；点击「查看请求」可重新读取状态并开始等待批准。已批准的请求会在刷新后离开待批准列表，可到「请求 / 历史」查看卡信息。没有待批准请求时页面会显示空状态提示。

App 不会替你批准购买请求。等待超过十分钟只表示 App 停止自动检查，不代表请求已取消。

6. 取消请求

  1. 在 请求 / 历史 中选中请求。
  2. 直接点击该行的 取消请求，或使用列表下方的 取消请求 Cancel。只有已创建、等待批准或已批准状态可以取消。
  3. 核对确认框中的商家和请求 ID，再点击 取消请求。
  4. Link 确认取消后，App 会清除该请求的卡信息并停止等待批准。请求会从活跃列表移除，打开「包含历史」即可查看；也可以刷新以重新读取服务端状态。

核对商家和请求 ID，再决定返回或取消；截图没有执行取消操作。

服务端可能拒绝取消某些状态的请求，App 会显示错误。

7. 查看历史

打开 包含历史，列表会重新读取历史请求，包括取消、过期等非活跃请求。选中记录后可以尝试显示详情，但过期或已结束的请求不保证还能返回完整卡信息。

这里是 spend request 历史：列表金额是请求中记录的金额，不是专门查询的商家实际扣款金额。当前 App 没有独立的商家交易流水、退款追踪或对账页面。核对实际扣款时，请结合商家收据和原付款方式最终入账记录。

常见问题

发生错误时，面板顶部会显示红色错误栏，保留 Link 返回的具体错误。切换页面、刷新和滚动不会清除它；点击「复制错误」可分享错误文字，点击 × 可关闭。创建失败会保留填写内容，不会跳转到待批准页。

遇到 amount must be at least $0.50 usd 时，将 USD 金额填写为至少 50。创建失败不会产生可批准的请求。若旧版本提示 expires_at is not supported for this client，退出并更新到 v2.5.6 或更新版本；当前创建表单已移除自定义截止时间。

情况 处理方式
没有活跃请求 打开「包含历史」，或创建新请求
付款方式列表为空 确认登录账户正确，点击「加载」；根据 Link 返回的提示处理账户或付款方式问题
创建按钮不可点击 检查必填字段，以及是否仍有操作在进行
提示金额或 URL 无效 金额填写正整数最小单位；URL 必须带 http:// 或 https://
pending_approval，没有卡号 打开本次请求的批准链接，完成批准后刷新
登录过期、HTTP 401 点击「登录 Link」重新授权，再刷新
卡号、地址或 CVC 显示 — 该次响应没有提供此字段；确认状态和批准情况，不能从 — 推断真实卡信息
收起面板后看不到卡信息 从菜单栏重新打开，选择请求并点击「显示卡信息 Show」

当前范围

  • Apple Silicon、macOS 13 或更新版本。
  • 支持中文和 English 即时切换，并保存语言偏好。
  • 每个创建请求包含一项商品，数量固定为 1。
  • 不自动下单、不自动批准、不自动启动、不提供退款操作。
  • 当前构建采用本地 ad-hoc 签名，没有 Apple 公证。

若出现 refresh_token is not active: status: revoked，表示保存的登录刷新凭证已失效。v2.5.7 起会恢复「登录 Link」按钮；点击并在 Link 中重新授权即可。无需分享任何 token。

没有批准链接或手机提示

更新到 v2.7.4 或更新版本，在「待批准」页刷新列表，选中请求，点击「获取批准链接」。created、pending_approval 和 requires_action 请求都会列出。获取成功后点击「在 Link 中批准请求」，在 Link 中完成批准，再刷新卡信息。若获取失败，查看顶部错误栏；不要仅因卡字段为空就重复创建。

多账户同时登录与切换

在账户信息上方的「账户」下拉框切换账户；点击「添加账户」启动新的 Link 授权，其他账户保持登录。在 Link 授权页面确认登录的是目标账户；Safari 可能仍登录着上一个账户。

每个账户独立保存 Keychain 凭证、API 会话、请求和消费额度。「退出登录」只退出当前账户；旧版本已有的登录保留为第一个账户。已保存的登录可在 App 重启后继续使用，实际受 Link 授权过期或撤销影响。每个账户的表单草稿在本次运行期间独立保留，切换时清除显示的卡凭证；已开始的批准状态检查可在 App 运行期间继续。操作或登录进行中暂不允许切换，可先点击「停止等待」取消登录。CLI 仍为独立的单账户工具。各账户额度独立展示，不合并也不提高额度。

已结束的请求无法取消

当 Link 返回终态取消冲突（HTTP 409 terminal state）时，App 会读取最新状态、禁用重复取消并清除该请求的卡信息显示。未包含历史时，已结束请求从活跃列表移除；勾选包含历史可查看最新状态。如果状态刷新失败，错误栏会明确提示，不会显示取消成功。

新版界面 (v2.9.0)

更新 App 和菜单栏图标；账户操作分组，额度可折叠；卡号、CVC 和有效期集中展示，各自提供复制按钮。早期截图用于说明流程，不代表最新样式。图标源文件： scripts/draw-icon.swift。

(v2.9.1) 添加账户时，Link 授权返回身份后检查重复登录：同一用户已登录时拒绝新增，仅清除本次新授权的本地凭证，返回原账户。优先比较用户 ID，缺失时比较邮箱；身份验证完成前不允许请求或付款操作。

钱包工具（v2.10.0）

  • 流水：选择 Link／外部连接／全部来源，填写可选的 YYYY-MM-DD 起止日期后刷新；支持加载下一页。空结果与权限不足分别提示。此处是 Link 或已连接金融账户返回的流水，不保证包含商家端完整结算明细。
  • 授权交易读取：用户点击并确认后，在 Link 请求读取 Link 和外部连接交易，保留原有授权范围。浏览器中必须授权当前账户；返回身份匹配后才替换本地凭证。未完成批准时原本地会话保留，远程授权撤销由 Link 控制。当前公开客户端或账户可能不支持部分权限，失败时展示 API 错误。
  • 付款卡：加载钱包付款方式，编辑昵称和默认状态，二次确认后保存到 Link。空昵称表示清空；新默认卡替换原默认卡。失败时保留上次已确认的本地显示值。
  • 身份验证：账户区展示需要验证／验证中／完成等状态，有官方操作链接时可跳转 Link。App 不收集身份证件或 SSN。

各页数据仅属于当前选中的 Link 账户。流水保留在内存，退出登录或会话失效时清除，不写入错误日志。开发验证仅使用模拟接口，没有授予真实权限、读取真实流水或修改真实钱包。

周期付款请求

在「创建」中填写付款方式、商家、金额与商品，再选择「付款周期」：默认单次，也可以选择天、周、月、年，并设置每 N 个周期（例如每 1 月、每 2 周）。用途自动加入周期说明，确认弹窗和请求列表也会显示周期。金额仍按所选币种的最小单位填写；创建前请核对金额、商家和周期，并在 Link 批准页面检查最终条款。

创建后打开批准链接，在 Link 完成批准。是否支持当前账户/客户端及周期规则，以 Link 返回为准；失败会显示在错误栏。可在请求列表查看状态并对可取消请求执行取消。App 不会自行定时创建请求或发起扣款；商家订阅需要在商家处单独管理，取消 Link 请求不会替你取消商家订阅。

开发验证使用模拟接口覆盖四种周期、单次请求及非法间隔，没有创建真实周期付款。

商家模板、订阅管理和状态通知（2.12.0）

商家模板

  1. 打开「创建」，填写商家、网址、商品、金额、币种和单次／周期设置。
  2. 展开「商家模板」，输入模板名称，点击「保存当前填写」。
  3. 下次从「选择模板」选择已保存模板，即可填入购买信息；选择模板会覆盖当前购买字段。
  4. 修改后再次保存会更新所选模板，也可以删除。保存模板不会创建付款请求。

模板按当前 App 账户槽位存储在本机偏好设置，重启后保留，不进行云同步；不保存付款方式 ID、卡号或 CVC。退出登录不会删除该槽位的模板。每次创建仍需选择付款方式、检查条款并在 Link 批准。

订阅管理

点击「订阅」自动加载当前账户的周期请求。选择一条查看周期、每期消费上限、币种、状态和请求到期时间；可查看卡信息、打开已有批准链接或取消仍可取消的请求。「包含历史」可显示已结束的周期请求。

每期上限不是已扣款金额。该页面管理 Link 周期付款凭证，不代表商家的完整订阅列表；不推算下次扣款日。取消凭证后仍需在商家处取消订阅。

macOS 状态通知

在面板底部开启「状态通知」，首次开启时允许 macOS 通知权限。App 运行期间会约每分钟检查已登录账户的 Link 请求状态，批准等待流程也会检测变化；对已观察到的批准、请求失败，以及 Link 返回的付款成功／失败变化发送通知。首次读取的历史记录和重复结果不重复通知。

通知不包含商家、金额、账户、卡号或 CVC。关闭开关会停止定时检查；退出 App 后不再检查，不是实时 Webhook。休眠、网络错误及 Link 数据延迟可能影响通知；付款最终结果请结合商家记录确认。若未收到通知，请到 macOS「系统设置 → 通知 → Link Card」检查权限与专注模式。

本版本完成离线模拟回归与构建验证；没有创建真实付款、修改真实钱包，也没有实测系统通知投递。

Safari 一键填卡（2.13.0）

在卡信息面板点击「填入 Safari…」，先检查当前付款网站，再确认填写。使用 macOS 的 Safari 自动化，不需要安装浏览器扩展、CLI、Node.js 或本地服务。

首次设置

  1. 在 Safari「设置 → 高级」开启「显示网页开发者功能」。
  2. 在 Safari「开发」菜单或开发者设置中，开启「允许来自 Apple 事件的 JavaScript / Allow JavaScript from Apple Events」。该选项的位置会随 Safari 版本变化。
  3. 首次点击填卡时，macOS 会询问是否允许 Link Card 控制 Safari，选择允许。若拒绝，可在「系统设置 → 隐私与安全性 → 自动化」中修改。
  4. 首次权限弹窗可能关闭菜单栏面板；授权后重新打开面板并显示卡信息即可。更新后若权限失效，请再次检查这些设置。

使用步骤

  1. 在 Safari 当前标签页打开 HTTPS 付款表单。
  2. 在 Link Card 显示已批准请求的卡信息，点击「填入 Safari…」。
  3. 核对确认页上的网站域名、请求商家和检测到的字段；若商家与当前网站不同，会额外提示。
  4. 点击「确认并填写」。App 在填写前再次核对 Safari 的页面 URL；页面切换后会停止，需要重新检查。
  5. 在 Safari 检查填入结果，再自行提交付款。App 不会点击付款或提交按钮。

支持常见卡号、CVC、组合／分开的有效期、月份／年份下拉框，以及明确标注为账单地址的字段；只填写 Link 已返回的姓名和地址，不推测缺失信息。不会自动填写配送地址、隐藏字段或无法识别的字段。跨域 iframe（许多支付平台使用）、Shadow DOM 和自定义支付控件可能无法填写，请使用原有复制按钮补齐。

凭证只在内存中传给 Safari，不写入文件、剪贴板、shell 参数或错误日志。关闭面板后，原有卡信息及结构化账单地址都会清除。页面确认的 URL 来自 Safari 本身；页面脚本只返回字段类型和填写结果，不返回字段值。

开发验证覆盖 DOM 模拟、HTTPS／页面切换拦截、字段格式、地址筛选和凭证清理；尚未在真实商家网页实测 Safari 权限或填写效果。运行 App 不需要 Node.js；开发者执行 ./test.sh 的 DOM 回归需要 Node.js 18+。

限额提醒与请求搜索筛选（2.14.0）

限额提醒

账户已登录且 Link 返回明确数据时，面板会显示限额提醒：每日或滚动 30 天剩余额度低于对应上限的 20% 时提示接近上限，返回的可用额度为零时显示零额度提醒。创建 USD 请求时，若填写金额超过返回的单笔上限、每日剩余或滚动 30 天剩余，会在表单内提示。

提醒只使用 Link 返回的美元等值数据；不从已用金额推算缺失的剩余值，不叠加多个账户，也不把其他币种直接换算为 USD。无限额、未返回或无效的数据不产生推测性提醒。提示不会阻止提交，数据可能变化，最终以 Link 批准结果为准；可使用「消费限额 → 刷新额度」更新数据。这是界面提醒，不额外发送系统通知。

搜索与筛选

「请求」「待批准」「订阅」页新增搜索框和状态、付款卡、请求类型筛选。搜索支持商家名称、网址、请求 ID 和用途，不区分大小写；多个词同时匹配。各筛选条件一起生效，可点击「清空筛选」重置。

付款卡按请求返回的付款方式 ID 分组；能匹配已加载钱包数据时显示昵称／品牌尾号，否则显示 ID。不会用生成虚拟卡的尾号猜测来源卡。类型可选择全部、单次或周期。

筛选仅作用于当前账户已加载的请求；查看旧请求需打开「包含历史」，待批准页只筛选待批准请求，订阅页只筛选周期请求。显示数量是当前页面匹配数／已加载数，不代表服务端全部记录。筛选隐藏选中请求时会清除选中状态和卡信息；新建请求成功后清空筛选，显示批准流程。
